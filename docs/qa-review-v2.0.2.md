## 仍需注意的产品问题

1. 岗位画像来自 21 份简历、每个方向 2–3 份，样本小且受 OCR 噪声影响，只能作为方向参考，不是实时岗位。
2. 画像是“该方向常见能力”的聚合，不是真实 JD；要推荐具体岗位，需要接真实 JD/招聘 API，或让用户粘贴 JD。
3. 证据分把画像高频技能都当作要求，硬技能分可能偏低；后续可按技能出现频率加权，或区分 must-have / nice-to-have。
4. 证据分和语义排名可能不一致（产品经理样本：证据 60，语义第 3）。UI 已分开标注，但产品上仍建议明确“证据分用来判断准备度，语义排名用来判断方向相近度”。
5. AI 回答偏长；系统 prompt 要求 4–6 句，但当前模型常给出更长的清单，需要在后端进一步约束。
6. 旧版本聊天记录会随升级保留，旧错误回复可能继续显示；建议后续做 schema/version migration，或提示用户清空对话。
7. PDF 简历导出仍列为下一步；当前 Markdown 导出是 P0。
8. 真机麦克风、真机视频仍需在物理设备上验证；模拟器只能验证录音启动与权限。

## 结论

三个模块的主链路可走通，核心阻塞问题已修复。产品目前是“方向画像匹配器 + 简历教练 + 本地数据设置”，不是实时招聘岗位推荐器；如果课程演示要强调“推荐岗位”，建议准备真实 JD 或在讲述中明确“推荐的是方向画像”。
